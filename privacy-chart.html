Enforcement Layers

Each feature uses one or more server-side layers to enforce privacy

Posts

RLS Policy Client Query

RLS uses CASE visibility with helper functions is_close_friend(), is_direct_friend(), is_friend_or_mutual(). Client also pre-filters by friendship type.

Plans

RLS Policy

RLS checks visibility = 'friends' (direct friend) or 'close_friends' (close friend). Client relies entirely on RLS.

Stories

RLS Policy

Same CASE visibility pattern as Posts. Also allows is_public_buzz = true stories through.

Planning / TBD

RLS Policy

RLS on night_statuses checks planning_visibility: uses is_close_friend() or is_direct_friend().

Location on Map

RPC Function Column Grants

get_profiles_safe() calls can_see_location() to mask lat/lng. Direct column grants on profiles block raw access to location fields.

Comments & Likes

RLS Policy

RLS checks if the viewer can see the parent post first (via friendship join), then allows access to comments/likes.

Yap Messages

RLS Policy

Simple policy: all authenticated users can read all yap messages. Intentionally public — anonymous venue chat.

Events

RLS Policy

All authenticated users can read all events. Client filters by city only.

Privacy Check Flow

What happens when User A tries to see User B's content

1
Client Query
App requests data from Supabase (e.g. posts, night_statuses)
2
Column Grants
Sensitive columns (lat, lng) blocked at column level on profiles
3
RLS Policy
Row-level security checks relationship + visibility setting per row
4
RPC Masking
For location: can_see_location() returns null if not permitted
5
Client Render
Only permitted data reaches the UI — filtered rows are never sent

Relationship Helper Functions

SQL functions used by RLS policies and RPC to determine relationships

is_direct_friend(a, b)

Returns true if A and B have an accepted friendship in the friendships table (either direction).

is_close_friend(a, b)

Returns true if A is in B's close_friends list. Directional — B chose to include A.

is_friend_or_mutual(a, b)

Returns true if A is a direct friend of B, OR if they share at least one mutual friend.

can_see_location(a, b)

Master location check. Reads B's location_sharing_level and calls the appropriate helper above.
