Definitions
DAU/WAU/MAU: distinct people with a recorded foreground open, screen view or successful action in rolling 24h/7d/30d windows. Coverage starts with instrumentation; older builds undercount. Failures, heartbeats and passive API requests alone do not make someone active.
Presence: foreground heartbeat at most 90 seconds old, excluding closed sessions. App sends every 30 seconds while active. Forced quits/network loss can remain visible for the 90-second grace period. This is not background GPS and not an exact simultaneous-online count.
Sessions: foreground segments, not the old 30-minute-deduplicated app-open convention. Duration sums heartbeat-confirmed intervals of at most 45 seconds; missing/offline intervals are omitted. Peak is sampled every minute and can miss short peaks. Historical aggregate samples reflect exclusions at collection time.
Retention: exact local calendar day after completed onboarding, with only fully elapsed D1/D7/D30 days in denominators. Existing grandfathered members are excluded. Raw events retained 90 days, cohort analysis covers the last 60 days. No pre-instrumentation backfill.
Nighttime check-in percentage: distinct night-active people with a check-in divided by night-active people in the selected window. Server night-mode rules and profile-city timezone apply; local nights roll at 5 AM. Check-ins are self-reported.
Social graph: canonical accepted pairs, demo/test exclusions and blocking. Current graph, not historical friendship retention. Average/three-friend rates use completed members.
Acquisition funnel: marked invited, claimed, completed, accepted friend, check-in in order; cohort starts no earlier than instrumentation. Marked invited is not proven receipt.
Map funnel: ordered open/map/venue in one foreground segment, with a check-in for that person within 30 minutes. No venue identity is collected for analytics, so this is temporal association, not proven same-venue attribution.
Friend funnel: user-level discovery then a request and acceptance of that request, followed by any supported social action within 7 days. Discovery/action can involve another friend; not exact per-friend attribution.
Notification funnel: unique recorded opens with server-validated destination. Relevant action matches destination ID within 30 minutes for DMs, plans and invites. An open can originate in the Activity list. APNs acceptance is not confirmed device delivery.
Growth: required onboarding nominations are not organic referrals. Claimed nominations per completed member is descriptive, not an organic viral coefficient. Install attribution remains unavailable.

Collection and performance
Existing successful-action triggers retained; group creation added. Client events allow fixed kinds/surfaces only. No raw paths, URLs, request bodies, error messages/stacks, contacts or coordinates. Stable UUIDs deduplicate retries per user. Batches <=40; client queue <=300 with 24h expiry. Server ingestion bounded per account. Foreground presence is never replayed from the offline queue. Captured auth token/account revision prevents queued events from becoming a new account's activity. Analytics never blocks an app action. New native hooks are saved separately and require a coordinated app release.

Operational alerts
Existing persistent incidents and acknowledgments retained. Added API failure/latency thresholds, reset-job evidence, database connection pressure, sudden foreground drop, email-worker and email-delivery failures. New jobs run each minute; dashboard signals are timestamp-only, with 15-second polling while visible. Acknowledge is not resolution. Activity drops can be natural; SQL-job success alone does not prove correct expiry behavior or an external provider response.
Native process crashes, terminated-app replay, pre-sign-in failures, full server trace correlation and an independent whole-database outage detector remain external integration gaps. Render error reporting in the native change is best effort and must not be called native crash reporting.
